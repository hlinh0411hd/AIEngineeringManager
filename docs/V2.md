# V2 — Automatic execution inside Tasks

## Daily use

1. Open Run.bat, choose Tasks, project, task type and allowed project access.
2. Enter the request and choose **Giao việc & chạy**. **Lưu để chạy sau** saves a draft without AI calls.
3. The manager creates an internal execution context automatically. Simple tasks run directly; complex tasks can receive a bounded plan. Automatic mode executes eligible steps and dependencies; SemiAutomatic previews AI and requests plan/step approval; Manual requires a selected model and retains supervision.
4. Stay in Tasks: **Tiến độ & kết quả** shows progress, **Các bước & cần duyệt** shows workers/decisions, and **Kế hoạch** shows the readable plan. Select a decision and use **Duyệt mục đang chọn & tiếp tục**, or reject it. Use **Xem kết quả bước** to inspect individual output.
5. **Xem kết quả / file thay đổi** opens the aggregate review. Apply explicit file proposals only after reviewing. **Xác nhận hoàn thành** is available after all steps finish; automatic internal progression does not claim human approval or independently verified output.
6. **Switch AI** stops/awaits the old worker, checkpoints and changes to an eligible explicit model. **Dừng & lưu** cancels execution and preserves progress. Ordinary Resume does not reset duration, usage or switch budgets. When the time window expires, progress and checkpoints are retained. In **Tiến độ & kết quả**, enter a new duration and choose **Gia hạn & tiếp tục**. This grants a new time window from now, preserving completed steps and consumed usage. Enter **0** for unlimited time.

No separate V2 tab or session creation is needed. Previous sessions appear as ordinary goal rows with their existing steps/history and budgets. Startup never silently resumes inference.

## Settings and planning

Settings contains reusable defaults: planning Auto/Always/Never, optional coordinator, duration, call/task/delegation/switch limits, automatic step progression, Away and test batching. Defaults apply when a task first starts. Scope and AI budgets remain fixed. The time window alone can be renewed explicitly on the existing task; ordinary Resume cannot renew it. Finite duration accepts 1–43200 minutes; 0 removes the session time limit. Per-provider execution timeout and call/switch budgets still apply. Automatic Away measures inactivity inside this app and cannot start work by itself.

Planning Auto uses deterministic request heuristics; this is not an AI complexity classifier. A plan needs at least two remaining calls and reserves one for execution. An explicitly permitted Planning model is preferred; otherwise an eligible cloud model already permitted for the original task kind can plan read-only within that scope. This does not add catalog permissions. Ollama is excluded from planning and Classification/Extraction stay direct. Coordinator attempts count against the same budget. Invalid plans are logged and fall back to the original scoped request. Rejected user plans do not silently run anyway.

Plan validation rejects unknown projects, access escalation, excess tasks, missing dependencies and cycles. Plan acceptance is atomic/idempotent. Workers may propose delegation; the C# manager validates model permissions, lineage, depth, cycles and remaining budgets. Providers cannot bypass manager approval via its protocol. Automatic mode can accept eligible routing/delegation; SemiAutomatic/Manual wait for decisions. CLI-internal behavior and billing are not independently metered.

Automatic internal progression applies only to Automatic mode and successful worker steps. It does not apply outstanding file proposals, bypass permission/approval decisions, claim tests passed or mark the final goal user-reviewed. Away can continue independent ready steps while blocked branches wait. Dependent steps within a goal remain sequential. Independent project goals can now run in a bounded shared pool, with project ownership shared with test jobs. See [model history and parallel workers](MODEL-PERFORMANCE-AND-PARALLELISM.md).

## Tests and permissions

Settings → advanced testing contains project-specific explicitly enabled native executable profiles, argument arrays, timeouts and validation scope. AI output cannot install commands or enable tests. Shell runners and Release/publish/pack arguments are rejected. Only enable commands for trusted projects; no runners are installed automatically.

Changed-file signals drive deterministic impact classification and batch coalescing; critical changes run enabled tests immediately, routine changes at batch end. File proposals enqueue tests after application. Source/command fingerprints prevent reuse of stale results. Unknown change signals require explicit **Xếp test cho task đang chọn**. Verification is separate from human completion: passing a configured profile only verifies its declared scope.

Provider/model and task permissions still apply. Select WriteProject before starting code edits and enable provider writes. Codex uses its verified sandbox flags; other supported CLI adapters return reviewed proposals. Ollama remains qualified only for categories it has actually passed. No provider is silently installed, authenticated or granted new model permissions.

## Data and practical limits

Schema 3 records the goal/step distinction. Existing schema-1/schema-2 databases receive an online SQLite backup beside the database (`manager.db.v1-<timestamp>.bak` or `.v2-...bak`) before upgrade. Old schema-2 executables reject schema 3 rather than treating goal rows as executable workers. Use Run.bat to choose the newest build. Production user data was not opened during development verification.

The app must remain open and the machine on. Interrupted execution recovers paused; tests recover interrupted. No background Windows service, unrestricted autonomous product launches, tool updater or unrestricted runtime quality guarantees were added. Historical routing now uses measured worker outcomes and explicit user feedback; it remains a heuristic. Existing connector interfaces remain extensible for later work.

Verification uses temporary fixture providers and isolated UI data, without paid inference. Live cloud coordination and long unattended runs were not performed. Build.bat remains the user-controlled Release path; development creates Debug verification output, no ZIP/RAR or installer.

## Data folder

Settings → **Đổi thư mục lưu data…** chooses an empty destination and copies task/project/index/settings/checkpoint/log/evaluation/plan/test records with SQLite online backup and integrity verification. The app must be idle. It opens the copied data immediately and remembers the path at the application root in data-location.json. The source database and prior migration backups remain untouched for recovery; it is no longer the active store. Project folders and provider installations are separate and are not moved.

New installations default to the application's Data folder, so this project stores active data on D:. First normal startup imports a legacy AppData database when no location is configured and the default database is absent. Both source and destination are protected by per-folder instance leases during import. If the old app is open, close it first. If storage selected in saved configuration is unavailable, startup stops with the path instead of opening blank data elsewhere. Diagnostic --data-dir runs neither import nor save location changes; the location button is disabled in this mode.
